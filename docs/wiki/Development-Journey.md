# 데이터 문제에서 실험 재설계까지

## V1: 넓은 비교가 먼저였다

초기에는 회계 baseline에서 표 모델·로컬 신경망·외부 시계열·foundation까지 폭넓게 비교했다. 그런데 저장 모델이 같은 값을 다시 내는 것과 과거 입력이 올바른 것은 별개였다. HON의 후속 공시가 과거 fiscal identity와 충돌하면서 이전 기록을 지우는 문제가 발견됐다.

첫 중간 수정은 알려진 중복을 남기는 방식이었지만 다른 기업의 `fy/fp` 모순을 해결하지 못했다. 특정 accession override를 최종 해법으로 삼지 않고 native 기간 날짜로 달력을 바꿨다. 중간안은 점수를 내지 않았고 기존 101개 출력 wave는 선택적으로 남기지 않았다.

## V1.3: 달력은 고쳤지만 feature는 남았다

69개 기업의 네 cutoff에 대해 미래 snapshot을 잘랐을 때 과거가 유지되는지 확인했다. 52/53주 회계연도와 17주 Q4는 정상적인 달력 사례였다. 날짜 간격 테스트와 직접 EPS truth의 보수적 기간 규칙을 혼동하지 않도록 했다.

이후 HVZ 계열의 큰 예측을 추적하면서 주식 수의 표 표시 단위를 발견했다. 17개 기본 recipe와 8개 ensemble이 노출됐다. 또 YTD로 이름 붙인 feature가 가장 이른 start를 선택하면서 TTM·단일 분기 context를 고르는 문제가 있었다. 147개 셀, 26개 기본 recipe와 8개 ensemble의 노출을 기록했다. V1을 깨끗한 회계 feature 실험으로 다시 부르지 않았다.

## V2: 수리와 모델 선택을 새로 분리했다

원문 단위를 확인한 두 MCD context만 수리했다. IBM의 companyfacts/submissions 날짜 충돌은 격리했다. 원문 검증이 없는 값을 크기만 보고 일괄 rescale하지 않았다.

13/14/17주 quarter는 이전에 알려진 기간 끝과 native context가 이어지는지 확인하도록 바꿨다. 데이터·선택 규칙을 고정한 뒤 모델을 학습했다. 원문으로 확인된 pre-2019 회계 셀이 0인 Track A는 모델이 아니라 데이터 단계에서 막혔다.

개발 구간의 46개 변형 중 대표와 ensemble을 정한 후 확인을 열었다. Lane A 6개 대표는 남았고 Lane C의 두 후보는 기준을 넘지 못했다. 확인에서 더 좋은 다른 후보를 보고 교체하지 않은 것이 마지막 결정이다.

## 확인을 마친 것과 새 holdout은 다르다

2019–2021 확인 구간과 2022 이후 관찰 구간은 앞선 연구에서 이미 접한 기간이다. 데이터 수리 뒤 선택 규칙을 지켰더라도, 이 기간이 다시 한 번도 보지 않은 holdout이 되지는 않는다. Lane A 후보를 남긴 판단은 해당 연구 계약 안의 결론이다. 새 시점·기업군에서의 독립 평가와 과거 원문 가용 시각의 근거는 여전히 필요하다. Lane C의 탈락과 Track A의 데이터 부족도 그 평가를 대신하지 않는다.
